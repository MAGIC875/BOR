1. SPA (Single Page Application)

Веб-приложение, где весь контент подгружается на одной странице, а переходы между “страницами” происходят без полной перезагрузки. В нашем проекте это React-приложение, где главная, каталог и страница “О сервисе” реализованы как компоненты.

---------------

2. Userflow

Пошаговый путь пользователя через сайт. В нашем случае это процесс от открытия главной страницы до успешного бронирования рабочего места. Помогает проектировать интерфейс и проверять удобство.

---------------

3. CTA (Call to Action)

Элемент на сайте, который призывает пользователя совершить действие — например, кнопка “Забронировать место”. CTA должен быть заметным и понятным.

---------------

4. Мок (Mock)

Имитированные данные для разработки, когда настоящего бэкенда ещё нет. Мы используем мок-данные для списка коворкингов и информации о бронировании.

---------------

5. Конверсия

Процент пользователей, которые выполнили целевое действие (например, забронировали место) от общего числа посетителей сайта.

---------------

6. Адаптивный дизайн

Дизайн, который корректно отображается на любых устройствах: мобильных телефонах, планшетах, ноутбуках и десктопах.

---------------

7. MVP (Minimum Viable Product)

Минимально рабочий продукт с базовым функционалом, который позволяет проверить идею. Для нас это сайт с главной, каталогом и страницей “О сервисе”, возможностью выбора и бронирования коворкингов.

---------------

8. Gitflow

Стандартная структура ветвления в git для управления разработкой. В нашем проекте будем использовать ветки: main, develop, feature/* и hotfix/*.

---------------

9. PR (Pull Request)

Запрос на внесение изменений в основную ветку проекта. С помощью PR можно проверять код, обсуждать улучшения и фиксировать изменения.

---------------

10. Карточка коворкинга

Блок на сайте с информацией о конкретном коворкинге: название, фото, цена, описание, рейтинг и кнопка “Забронировать”.
